# SPEC — what may be claimed

⚠ **This file holds what this stack may claim about itself.** ⚠ Nothing else.
**How to work** is [`CLAUDE.md`](../CLAUDE.md); **how to write it** is
[`.claude/rules/`](../.claude/rules/); **why** is [`adr/`](adr/).

⚠ **Never write a count in here** (`CLAUDE.md` §6, and the reason below).
⚠ **Counts are announced by whatever produced them**, at the moment it runs.
⚠ **A count written down here is stale from the moment it is written, and it makes every
parallel change conflict.**

---

## 1. What this implements

⚠ **A row goes in here only once the behaviour exists and a check asserts it.**
⚠ **Planned is not implemented** (`CLAUDE.md` §1).

⚠ **"What asserts it" names a case, not a file.** ⚠ **A file name says where to look; it does not
say that anything in there asserts this claim** — and a reader takes the column at its word.
⚠ **Run the case before filling the row in, and read whether it covers every clause of the claim.**
⚠ **Grounds: this went wrong here** (`CLAUDE.md` §9). `tests/static.sh` `spec_names_checks_that_exist`
stops a row that names an entry point and no case, a row that names nothing at all, a case name that
does not exist, and a case with no entry point in front of it to attribute it to.
⚠ **Nothing stops a case that exists and does not cover the clause** — ⚠ **reading the case is still
the reviewer's job, and that is the half this table got wrong.**

## 2. What this deliberately does not implement

⚠ **A gap named here is a decision.** ⚠ **An unnamed gap is just something not done yet** —
they are different things and the difference is stated, not implied.

| Not implemented | Deliberate? | Why |
|---|---|---|
| Interpreting anything above an ICMP echo message | ⚠ **no** | ⚠ Not yet written, and not a decision. The stack reads the ethernet header, an ARP packet, an IPv4 header and an ICMP echo message, answers the last two, and stops there |
| Reading any ICMP type but an echo request | yes | ⚠ Destination unreachable, time exceeded and redirect were not read in RFC 792 and are not implemented. ⚠ **An echo reply is among them**: one is built, and one arriving is a `Type` we do not act on (ADR 0011 Owner Decision 2). ⚠ All of them are counted apart from a malformed message |
| Reading an 802.1Q VLAN tag | yes | ⚠ `0x8100` is read as any other length/type value and the tag itself is not read (ADR 0003). ⚠ So for a tagged frame that value does not name what the frame carries |
| ⚠ A count of frames the kernel dropped | yes | ⚠ The harness cannot observe it. A drop happens in the kernel's queue, and printing a number we did not measure is a guess dressed as one (`CLAUDE.md` §1) |
| ⚠ Counting a frame shorter than an ethernet header | ⚠ **no, and it cannot be reached** | ⚠ The code is there and `ethernet_parse_header` answers for it (`tests/static.sh` `ethernet_header`), ⚠ **but the counter can never move on a TAP device.** ⚠ Measured 2026-08-28: `AF_PACKET` refuses 13 octets with `EINVAL`, ⚠ **and so does the tun fd** — 0, 1 and 13 octets, measured at hidetzu/tcpip-stack#17 and recorded in `src/tap.h`. ⚠ **Not a decision and not an omission: something measured to be unreachable here.** ⚠ The code stays, because a TUN device or another entry point could reach it and ⚠ removing it would let that fall silently (hidetzu/tcpip-stack#52) |
| TUN (layer 3) mode | yes | The first milestone is ethernet, so the harness attaches as a TAP |
| An ARP cache | yes | ⚠ Answering needs nothing remembered — everything the reply carries is in the request or is our own address. ⚠ What RFC 826 says beyond replying was not read, so this is a decision about what we do, not a reading of the document (ADR 0008) |
| Routing, a routing table, a neighbour cache | yes | ⚠ A reply goes back to the ethernet and IPv4 addresses the frame that asked came from. ⚠ **A TCP connection keeps the requester's hardware address**, because a retransmission has no arriving frame to read it from (hidetzu/tcpip-stack#59) — ⚠ **one field of one connection, not reachable by address, invisible to any other connection, and gone when the connection is.** ⚠ **That is not a table, and calling it one would be a wider claim than what is there.** ⚠ Nothing else is remembered, so it answers whoever is on the other end of the device and nothing else |
| ⚠ Anything that needs a clock | ⚠ **no** | ⚠ **A clock exists and nothing reads it for a decision yet** (`src/moment.c`, hidetzu/tcpip-stack#56). ⚠ **So nothing times out and nothing of ours is retransmitted** — ⚠ that gap is not closed by having the clock. ⚠ **The peer's timer still covers the handshake**: the Linux kernel retransmits an unanswered SYN 7 times in one `connect()` (3 runs of 3, 2026-08-28). ⚠ **It stops covering us the moment data or closing is involved** (ADR 0015, ADR 0018) |
| ⚠ More than one connection at a time | yes | ⚠ Room for one. ⚠ **Nothing frees a block on its own**, so a larger number would reach the same wall by the same path (ADR 0015). ⚠ The one that does not fit is counted apart and reported as ours, not the sender's |
| ⚠ Negative advice to a routing layer at R1 | ⚠ **no** | ⚠ **R1 exists since hidetzu/tcpip-stack#131** — `SHLD-10` is **met**, at its own three retransmissions — and ⚠ **the threshold is crossed, counted and said, once.** ⚠ **RFC 9293 `MUST-20` (b) asks for negative advice to the IP layer, and there is none here to advise**: nothing routes and there is no gateway to diagnose. ⚠ **A line on a terminal is not that**, and calling it one would be the shape `CLAUDE.md` §1 forbids |
| ⚠ A send buffer | ⚠ **no** | ⚠ **The octets are a pattern computed from the sequence offset** (`handshake_octet_at`), ⚠ **so nothing is allocated and nothing has to be freed** (ADR 0015). ⚠ **This stack cannot send data it was handed** — ⚠ only data it can compute — and ⚠ **`--send` names a count, not content** |
| ⚠ A segment carrying more than 1460 octets | ⚠ **no** | ⚠ `TCP_SEGMENT_DATA_MOST` is 1460, ⚠ **a ceiling on the buffer and not a protocol number.** ⚠ **On a device with a larger MTU the effective send MSS would allow more and this bounds it instead** — ⚠ said plainly because it is a limit of ours, ⚠ **not RFC 9293 `MUST-16`'s, which is met** |
| ⚠ Anything a TCP connection does that is not opening it or closing it | ⚠ **no** | ⚠ Not yet written, and not a decision. ⚠ **What used to stand here as an inference is measured now, and the gap it named is closed.** ⚠ Until hidetzu/tcpip-stack#64 the answer's window was 0 and the kernel sent bare `ACK`s repeatedly with no `FIN` and no `RST`; ⚠ **that they were probes provoked by the window was recorded as an inference.** ⚠ **Measured 2026-08-29, same conditions as §3**: with the window at 0 a `close()` produces no `FIN` at all; ⚠ **with it at 1 the `FIN` arrives, five times**; and ⚠ **once that `FIN` is answered the kernel sends it once and stops.** ⚠ What is left unwritten is everything between opening and closing — ⚠ **sending data of our own, and anything a user of this stack would ask for** |
| ⚠ Closing a connection this stack did not have closed on it | ⚠ **no** | ⚠ **Nothing here decides to close on its own.** ⚠ RFC 793's `FIN-WAIT-1`, `FIN-WAIT-2`, `CLOSING` and `TIME-WAIT` all belong to the side that closes first, and ⚠ **none of them exists here** — a state with no transition into it would be a claim that we implement it. ⚠ Not a decision that closing first is wrong; ⚠ **there is no user to ask for it** (ADR 0022) |
| ⚠ Holding a finished connection for 2 MSL | ⚠ **no, and it is not ours to hold** | ⚠ `TIME-WAIT` is the closing side's, and ⚠ **this stack never closes first.** ⚠ **Measured 2026-08-29**: after our close is acknowledged, `ss` on the peer reports `TIME-WAIT` — ⚠ **the peer's own 2 MSL, which nothing here can shorten.** ⚠ What `ss` should show is hidetzu/tcpip-stack#67's |
| ⚠ Freeing a connection that neither finished nor timed out | ⚠ **no** | ⚠ **Nothing frees a block on its own** (ADR 0015). ⚠ Three things free one and nothing else does: ⚠ **our close being acknowledged**, ⚠ **a timer running out** — on a handshake nobody confirmed or a close nobody acknowledged — and the program stopping. ⚠ So a connection that reached `ESTABLISHED` and is simply left alone ⚠ **holds the one block for ever**, and the next `SYN` is refused for want of room. ⚠ Not a decision that it should stay that way |
| ⚠ Refusing a segment addressed to a **directed** broadcast | ⚠ **no** | ⚠ **RFC 9293 `MUST-57` is met in part** since hidetzu/tcpip-stack#99: the limited broadcast `255.255.255.255` and multicast `224.0.0.0/4` are refused before any state is taken, ⚠ **and a directed broadcast such as `10.0.0.255` is not.** ⚠ **It cannot be told from a host address without a netmask, and nothing here has one** — ⚠ `--ipv4` is the only address this stack is given. ⚠ **Named as partial rather than claimed met** (`docs/conformance.md`) |
| ⚠ Refusing a `SYN` whose SOURCE is a **directed broadcast** | ⚠ **no** | ⚠ **RFC 9293 `MUST-63`: "An incoming SYN with an invalid source address MUST be ignored either by TCP or by the IP layer."** ⚠ **Met in part since hidetzu/tcpip-stack#112** — §1 says which part. ⚠ **Still not met**: RFC 1122 §3.2.1.3 (d), (e) and (f), each "MUST NOT be used as a source address" — ⚠ **a directed broadcast cannot be told from a host address without a netmask, and nothing here has one.** ⚠ **The same gap `MUST-57` has, for the same reason**, and ⚠ **the check asserts such a source IS still answered** so this row cannot go stale in silence |
| ⚠ Asserting that an option list not on a word boundary is walked | ⚠ **no** | ⚠ **The behaviour is there and nothing asserts it.** RFC 9293 `MUST-64`: "receivers MUST be prepared to process options even if they do not begin on a word boundary" — ⚠ **met, because the walk is byte-wise.** ⚠ **No case feeds an unaligned option on purpose**; two cases happen to exercise it, ⚠ **which is not the same as asserting it.** ⚠ **A gap in the checks and not in the code** — ⚠ rewrite the walk word-wise tomorrow and every case stays green |
| ⚠ The urgent mechanism | ⚠ **no** | ⚠ **RFC 9293 `MUST-30`: "TCP implementations MUST still include support for the urgent mechanism"** — ⚠ **and `MUST-31`, `MUST-32`, `MUST-33`, `MUST-62` with it.** ⚠ **The bit and the pointer ARE read** — ⚠ `MUST-66` is **met** (hidetzu/tcpip-stack#101) and a segment carrying `URG` is counted and reported as `urgent and nobody to tell` — ⚠ **reading a field is not supporting a mechanism.** ⚠ `SHLD-13` tells new applications not to use it and ⚠ **the document still requires the support** |
| ⚠ Reading an ICMP error's quoted datagram as a whole one | ⚠ **no** | ⚠ **It is not one.** RFC 792 carries back "the internet header plus the first 64 bits of the original datagram's data" and ⚠ **nothing more**, so ⚠ **`Total Length` almost always names more octets than are present** — ⚠ **and that is the sender being correct.** ⚠ `ipv4_parse_quoted_header` reads it without demanding the rest; ⚠ **`IPV4_PARSE_OK` from it means "the header is readable" and never "the datagram is whole"**, and no caller may take it for the second |
| ⚠ **An application-facing TCP API, and a routing-layer consumer** | ⚠ **no**, ⚠ **by decision for v0.1.0** | ⚠ **The two absences nine unmet requirements hang from**, ⚠ **and they are one decision rather than nine oversights** (ADR 0037). ⚠ **Nothing calls `OPEN`, `SEND`, `RECEIVE`, `CLOSE` or `ABORT`** (ADR 0022), and ⚠ **nothing routes**, so there is no layer to give negative advice to. ⚠ **NO VERDICT MOVES BECAUSE OF THIS.** ⚠ `docs/conformance.md`'s legend says a bare `MUST` is never *does not arise*, and ⚠ **a scope decision does not make a requirement inapplicable** — ⚠ it says why the requirement is unmet and that being unmet was chosen. ⚠ **`MUST-20` (b), `MUST-30`, `MUST-31`, `MUST-32`, `MUST-33`, `MUST-43`, `MUST-47`, `MUST-48`, `MUST-62` stay not met** |
| ⚠ An interface for an application | ⚠ **no** | ⚠ **RFC 9293 `MUST-47`** (a mechanism for reporting soft errors), ⚠ **`MUST-48`** (the application sets the Differentiated Services field), ⚠ **`MUST-43`** (the `OPEN` call's local IP address parameter). ⚠ **There is no user of this stack** (ADR 0022). ⚠ **`--ipv4` and `--ttl` give a caller two of these effects in another shape**, and ⚠ **an effect in a different shape is not the requirement met** — the reading `MUST-20` R2 got at hidetzu/tcpip-stack#96 |
| ⚠ ECN | ⚠ **no**, ⚠ **by decision** | ⚠ **RFC 9293's entire content about ECN is three things**: §3.1 defines `CWR` and `ECE` as bit positions "see [6]", §3.8.2's `SHLD-8` — "A TCP endpoint SHOULD implement ECN as described in RFC 3168" — and one glossary line. ⚠ **`[6]` is RFC 3168 every time**, and ⚠ **ADR 0024's scope table names it as OUT of the baseline.** ⚠ **So `SHLD-8` is a `SHOULD` refused with a reason** (Owner Decision, hidetzu/tcpip-stack#139), ⚠ **not one ignored** — the same shape `SHLD-1`'s secret has. ⚠ **What this stack does instead is the correct thing for a non-participant**: an ECN-setup `SYN` opens the connection (hidetzu/tcpip-stack#86) and ⚠ **our answer carries neither bit**, so both ends know it is not an ECN connection. ⚠ **Measured on the wire**: the kernel offered `CWR|ECE|SYN` and our answer carried `SYN|ACK` alone. ⚠ **Until hidetzu/tcpip-stack#139 nothing asserted that** — ⚠ a build that started setting `ECE` would have claimed a mechanism it does not have with every check green |
| ⚠ An internet header carrying Options | ⚠ **no** | ⚠ A datagram whose `IHL` is greater than 5 is refused as ⚠ **well-formed but unsupported**, counted on its own (ADR 0010). ⚠ **So RFC 9293 `MUST-50` and `MUST-53` do not arise — because a refusal of ours keeps their condition false**, which is a different thing from a condition that cannot occur. ⚠ **`MUST-53` is the one to watch**: "When a TCP connection is OPENed passively and a packet arrives with a completed IP Source Route Option ... MUST save the return route". ⚠ **Every connection here IS opened passively**, so ⚠ **it becomes live the day `IHL > 5` is accepted** |
| ⚠ RFC 5961's narrower acceptance test | ⚠ **no** | ⚠ **RFC 9293 `MAY-12`**: RFC 5961 §5's mitigation for blind data injection. ⚠ **Not taken**, and ⚠ **worth naming because this stack takes segments from strangers**: the acceptance test for an `ACK` is the window check §3.10.7.4 gives and ⚠ **not RFC 5961's.** ⚠ **A `MAY` refused is a decision only if the decision was taken** — ⚠ **this one was not, and this row is the record of it** |
| ⚠ Asserting that a failed MTU read takes its own branch | ⚠ **no** | ⚠ **The stack asks the device how large a frame it carries, and says so** (§1). ⚠ **When it cannot be asked it says that instead, and says the number it carries on with was chosen here** — ⚠ **the SENTENCE is asserted** (`tests/static.sh` `report_lines` → `the_mtu_lines_say_which_it_was`). ⚠ **That the branch is TAKEN is not asserted.** ⚠ **Measured 2026-08-29**: deleting the whole `else` at the call site left every check green. ⚠ **No harness here can make the read fail** — the device exists by the time it is asked, because the fd created it — and ⚠ **contriving a failure would be testing the contrivance** |
| ⚠ Holding a segment that arrives ahead of what we are waiting for | ⚠ **no** | ⚠ **RFC 793: "segments with higher beginning sequence numbers may be held for later processing."** ⚠ **Nothing here holds anything** — such a segment is refused and counted, not kept. ⚠ **The clause that used to stand here — that a duplicate and a segment ahead were not told apart — is gone rather than softened** (hidetzu/tcpip-stack#76): ⚠ **they are two answers, two sentences and two counters now**, and the sum is what the one number used to be |
| ⚠ Sending a reset, or an ack for a retransmitted SYN | ⚠ **no** | ⚠ Not yet written, and not a decision. ⚠ **Three places RFC 793 §3.9 says to form a segment produce a counted reason and no segment**: a reset for an acknowledgment arriving in `LISTEN`, a reset for an acknowledgment outside the window in `SYN-RECEIVED`, and an ack for a retransmitted SYN |
| ⚠ An initial sequence number an outsider cannot guess | ⚠ **no** | ⚠ **RFC 9293 `MUST-8` is met** since hidetzu/tcpip-stack#98: the number is clock-driven, one step every 4 microseconds, ⚠ **and it is no longer the constant `0xdeadbeef`.** ⚠ **`SHLD-1` is refused with a reason**: its `ISN = M + F(..., secretkey)` needs a secret key and a pseudo-random function, ⚠ **and this repository has neither and no cryptographic dependency** (`CLAUDE.md` §3). ⚠ **So the number is still guessable by anyone who can read a clock** — ⚠ a weakness outside a private namespace, and ⚠ **a `SHOULD` refused is a decision, not an omission** (`docs/conformance.md`) |
| ⚠ Implementing any TCP option **but the MSS Option** | ⚠ **no** | ⚠ **One is implemented since hidetzu/tcpip-stack#123** — kind 2, sent on the `SYN,ACK` and read on arrival. ⚠ **Every other kind is walked and not interpreted** (ADR 0013): the walk checks the list is well formed and ⚠ **an option it does not act on is not a reason to refuse the segment** (`.claude/rules/layers.md`: malformed and unsupported are different answers) |
| ⚠ Anything UDP | ⚠ **no** | ⚠ Not yet written, and not a decision. ⚠ A datagram carrying it comes back as a protocol we do not act on, counted apart from every other reason |
| Reassembling IPv4 fragments | yes | ⚠ A fragment comes back as its own answer and ⚠ **nothing is reassembled**. ⚠ Kept apart from a version we do not support so the two are never one number (ADR 0010). ⚠ What RFC 791 says about reassembly was not read |
| Reading IPv4 `Options` | yes | ⚠ A header longer than five 32-bit words is declined as unsupported rather than skipped over. ⚠ Generalise once something needs them, never before (ADR 0010) |

## ⚠ 2-1. Which document binds

⚠ **RFC 9293 (STD 7) is the normative baseline for TCP** (ADR 0024). ⚠ The question was raised in hidetzu/tcpip-stack#70, ⚠ **which is a pull request and not an issue** — it never had one, and ADR 0024 is where it is settled.
⚠ **RFC 793 is informative** — historical explanation and design intent. ⚠ What RFC 9293 leaves to
other RFCs is added ⚠ **one function at a time, when that function is implemented.**

⚠ **Every RFC 793 quotation already in this file stays**, and is what RFC 793 says. ⚠ **What changed
is which document a new claim is held to, and which settles a disagreement.**

⚠ **It is not free.** ⚠ RFC 793 uses no RFC 2119 keywords in capitals — measured, 0 — and RFC 9293
uses 203 `MUST` and 38 `SHOULD`. ⚠ **Several claims here rest on the shape "the document states X and
does not tell a receiver what to do", with the conclusion recorded as ours.**

⚠ **They were re-read one at a time on 2026-08-29** (hidetzu/tcpip-stack#87), ⚠ **with the sentence
of RFC 9293 each was judged against, quoted where the claim is recorded.**

| Claim, and where it is recorded | ⚠ Verdict |
|---|---|
| A non-zero `Reserved` is malformed (ADR 0013) | ⚠ **Contradicted, and on two grounds that are not the same kind** — ⚠ §3.1 defines the field as **four** bits and this build read six, ⚠ **which is a definition and not a keyword matter**; and ⚠ **"must be ignored" is lowercase prose**, so ignoring it is grounded in the measurement, not the sentence. Done: hidetzu/tcpip-stack#86, ⚠ **the grounds corrected at #92** |
| A `Data Offset` below 5 is malformed (ADR 0013, `src/tcp.h`) | ⚠ **The document's now** — "present only when DOffset > 5" (§3.1). ⚠ No code changed |
| A retransmitted `SYN` is not the in-window `SYN` error (ADR 0016) | ⚠ **Still ours** — Table 6 gives the test, ⚠ **placing the step is ours** |
| `SND.UNA =< SEG.ACK =< SND.NXT` accepts both ends (ADR 0016) | ⚠ **The document's, and always was** — reading its sentence, not extending it |
| The checksum is decided before any field's content (ADR 0014) | ⚠ **Still ours** — §3.1 requires the check (MUST-3) and ⚠ **says nothing about when** |
| 1000 ms between answers (ADR 0019) | ⚠ **Now ours too** — ⚠ RFC 9293 has no `LBOUND` and no "e.g., 1 second", measured. ⚠ It defers to RFC 6298, which clause 3 does not pull in |
| 3000 ms before giving up (ADR 0019) | ⚠ **Still ours**, and never claimed otherwise |
| A `FIN`'s arrival is the `CLOSE` (ADR 0022) | ⚠ **Still ours** — §3.10.4 and §3.6 keep the local user, ⚠ **and there is still none here** |
| One segment carrying `FIN,ACK` (ADR 0023) | ⚠ **Still ours** — §3.10.4 says "send a FIN segment, enter LAST-ACK state" and ⚠ **nothing about how many segments** |
| `Protocol` 6 is an observation, not the document's (`src/tcp.h`) | ⚠ **Still ours** — §3.1 says only "PTCL: the protocol number from the IP header" |
| `CLOSE-WAIT` → `LAST-ACK` (ADR 0022) | ⚠ **The document's** — §3.10.4, settled at hidetzu/tcpip-stack#66 before this pass |

⚠ **ADR 0010 and ADR 0011 are out of scope for that pass and say so**: they draw the same shape for
IPv4 and ICMP and are held to RFC 791 and RFC 792, ⚠ **which ADR 0024 did not move.**

⚠ **One changed behaviour.** ⚠ hidetzu/tcpip-stack#86 made `Reserved` four bits — ⚠ **`tcp_counts.malformed`
means less than it did**, four causes to three, and that is said rather than left for the number to
change meaning quietly.

### ⚠ One verdict of that pass was itself overstated, and is corrected here

⚠ **hidetzu/tcpip-stack#87 called a second claim "contradicted" and cut hidetzu/tcpip-stack#89 for
it**: RFC 9293 §3.10.7.4 describes an acknowledgment for an unacceptable segment, and a retransmitted
`SYN` draws none from us.

⚠ **That was wrong, and it is the very failure ADR 0024 warned about.** ⚠ The sentence reads "an
acknowledgment **should** be sent in reply" ⚠ **in lowercase**, and RFC 9293 §2 says the keywords
bind "when, and only when, they appear in all capitals". ⚠ **There is no labelled `MUST` or `SHOULD`
in that passage.** ⚠ So it is the document **describing** behaviour, not requiring it — ⚠ and calling
it a contradiction collapsed `MUST`, `SHOULD` and prose into one thing (`CLAUDE.md` §1).

⚠ **Measured 2026-08-29 before deciding**: the acknowledgment was implemented and the peer's
behaviour was ⚠ **identical** — six retransmitted `SYN`s and a `connect()` failing after six seconds,
with it and without it. ⚠ A peer in `SYN-SENT` drops a bare `ACK` carrying no `SYN`.

⚠ **So it is not implemented** (hidetzu/tcpip-stack#89, closed): ⚠ **not required, and measured to
change nothing.** ⚠ Recorded here with its grounds rather than left as an open issue that looked like
a conformance failure.

⚠ **What hidetzu/tcpip-stack#80 does is unaffected**, and its grounds were always the measurement and
not the sentence: ⚠ with our acknowledgment for data dropped on purpose the peer's `Send-Q` sticks,
and ⚠ **this is what lets it reach 0.** ⚠ **The comments that read as though the document asked for
it were corrected in the same pass.**

⚠ **One more was found and is deliberately not an issue**: RFC 9293 §3.10.7.4 says an acceptable
`SYN` in `SYN-RECEIVED` on a passive `OPEN` should "return this connection to the LISTEN state", and
⚠ **this build does not.** ⚠ **Lowercase again, and unmeasured** — ⚠ named here so it is not lost.
